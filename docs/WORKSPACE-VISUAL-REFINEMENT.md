This records the first visual pass. See [the workflow continuation](WORKFLOW-POLISH.md)

the measurements in this report describe the first-pass result.

Local development on `feature/workspace-visual-refinement`, based on

## Design audit and changes

The existing navy/teal identity and functional chart were worth preserving. The
main problem was hierarchy: a full mobile navigation grid, repeated wordmarks,
large introductory header and stacked chart controls pushed the market below
the first screen. At tablet sizes the fixed sidebar reduced the plot width, and
the observed price could break across lines. Multiple bordered surfaces inside
the assessment rail added visual weight without adding information.

- Phone/tablet navigation uses the existing nine destinations in one horizontal
  row. Keyboard focus reveals the whole focused destination in both directions.
  Tablet navigation no longer reserves a fixed sidebar.
- A compact market workspace header replaces the repeated promotional masthead.
  On phones its heading remains available to assistive technology; visible space
  is allocated to capability status, market selection and the analysis action.
- The THN navy/teal system has calmer surfaces, consistent radii and clear focus
  outlines. Arabic headings retain natural letter spacing. Light mode has its
  own matching surface and contrast tokens.
- The original chart is retained across Dashboard and Terminal. Drawing controls
  sit alongside the mobile plot; at extreme zoom they wrap above the full-width
  plot. Larger targets and readable control text remain available.
- The market assessment rail uses dividers instead of nested summary cards.
  Provider details, proxy warnings, observed-close labels, capability limits and
  original advanced tools remain available.
- Observed prices remain on one line at ordinary desktop/tablet/phone widths;
  extreme zoom permits wrapping rather than losing content.

Remaining design opportunities are the market table's competing row actions,
the length and hierarchy of secondary research/risk forms, and duplicated
explanatory content below the main chart. Those need their own workflow review;
this pass prioritizes the shared shell and primary chart workspace. A configurable
watchlist beside the chart is not added by this change.

## Measured result

Same Chromium engine and offline provider fixture, EN/dark, 1440×1000,
768×1000 and 390×844 CSS viewports. Plot bounds refer to the existing `qCandles`
canvas, including its axis/indicator regions. Visible height is intersection
with the first viewport, not a claim about the entire chart fitting on screen.

The mobile plot is 30px narrower because its drawing controls occupy a persistent
side rail. This keeps those controls accessible while removing a full row above
the plot. The visible mobile chart and the wider tablet workspace are the main
improvements; the desktop layout remains familiar.

## Evidence and acceptance

Local, fixture-based captures are in ignored `work/design-refinement/`:

- `before-{dashboard,trading}-{1440,768,390}.png`: original full-page captures.
- `candidate-{dashboard,trading}-{1440,768,390}-{en-dark,ar-light}.png`:
  current first-viewport captures, generated by the focused regression suite.
- `validation.json`: 24 language/theme/viewport/view measurements, chart identity,
  unbroken price text, keyboard navigation and runtime-error checks.
- `full-gate/`: logs from the complete packaged browser gate.

These captures are not live-provider or Production evidence. Owner visual
acceptance remains separate from automated validation. Manual iPhone/Safari and
real TradingView reliability remain unverified. Horizontal navigation requires
scrolling for secondary destinations on smaller screens.

No numerical engine, account behavior, provider adapter, broker integration,
dependency declaration, lockfile or deployment setting changed. No push, merge,
deployment, real inference, broker authentication or trading was performed.

The new `browser_visual_refinement.py` regression is registered in the existing
browser runner. It tests first-viewport plot visibility rather than accepting
an overflow-free page whose chart is entirely below the fold. The assisted-desk
navigation test now focuses each destination before its original containment
assertion and real route click. This explicitly replaces the old assumption
that all nine mobile buttons fit onscreen simultaneously with the compact
navigation contract. No containment assertion, route or financial check was
removed or disabled.
